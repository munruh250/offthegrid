Three layers, one map

01

Territory

Natural-shaped parcels around named places. Always visible, this is the map's resting state — what you'd glance at mid-camp-chore.

02

Contour (elevation-gated)

Isolines only render above a height threshold and fade in with elevation. Lowland territories stay clean and legible; ridgelines and saddles earn topographic detail, because that's where it actually matters for planning a route.

03

Route (on demand)

Not a permanent network — a line that appears when you've chosen a destination, in the same style as the node-network study. Distance, time and rough slot cost render at the midpoint.

02

How hard the gate should be

Same elevation-gated contour idea, two different curves. This is the actual decision left to make once the concept is agreed.

Why the route disappears until asked for. A always-on path network implies the game already knows the best way there — which undercuts the show's own texture of genuinely not knowing what's over the ridge. Making the line appear only on request keeps the territory layer as the default read, and turns "where's the fastest way to the ridge" into a small, real decision rather than furniture.

Numbers on the route line are illustrative — placeholder scaling from pixel distance, not the real travel-cost formula. Once relocation and travel costs are settled in the balance doc, this is where that formula surfaces to the player.

Tap targets. Small territories are still below the 44px comfortable minimum at this frame size. Hit-testing here uses nearest-centre with no minimum radius, which is generous for a mockup but would need a real minimum touch radius in production — same caution as the hex and node studies.
